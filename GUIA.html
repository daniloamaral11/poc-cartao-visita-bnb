Cartão de Visita Digital

Guia de replicação. Ao final você terá um cadastro que grava em um Object, gera uma página própria para cada pessoa, exporta o cartão em PNG e entrega um link compartilhável — tudo com recursos nativos, sem módulo OSGi, sem client extension e sem biblioteca externa.

Tudo pela interface

Nenhum passo exige linha de comando. Os únicos comandos no guia são chamadas curl de verificação, no fim — e existem porque testar permissão de visitante anônimo é mais confiável assim do que abrindo janela privada.

Arquitetura

Seis peças nativas se encaixam. O que costuma confundir é que três delas têm nomes parecidos e papéis distintos — vale ler esta tabela antes de começar a clicar.

PeçaPapel na POCOnde fica
Object Modelo de dados. Ao publicar, gera tabela, tela de admin, permissões e API REST. Menu → Objects
Fragment Bloco de HTML/CSS/JS reutilizável. É onde mora todo o código da POC. Design → Fragments
Form Container Fragmento que vira formulário ao ser apontado para um Object. Gera os inputs sozinho. no editor de página
Display Page Template Molde que renderiza um registro. Dá URL própria a cada cartão. Design → Page Templates
Collection Consulta salva. Dinâmica: cadastrou, apareceu. Não desenha nada. Content → Collections
Collection Display Fragmento que desenha uma Collection. Não busca nada — anda sempre em par com ela. no editor de página

Fluxo final

/cadastro-de-cartao        Form Container grava no Object
        ↓                  Success Action: Go to Entry Display Page
/e/<template>/<id>         Display Page Template renderiza o cartão
        ↓                  fragmento Cartao Visita
   PNG + link              canvas.toDataURL() e navigator.clipboard

/galeria                   Collection Display lista tudo e linka cada item

Passo a passo

A ordem importa: os passos 4 e 5 destravam opções que os passos 6 e 8 precisam encontrar na interface. Fora de ordem, você vai procurar menus que ainda não existem.

1

Criar a picklist Unidade

Menu → Objects → Picklists → New

Nome Unidade. Adicione três entradas:

Gerencia    RH    TI

Picklists são domínios fechados reutilizáveis entre Objects. O valor gravado é o par chave/rótulo — na API aparece como {"key": "TI"}, não como texto puro.

2

Criar e publicar o Object

Menu → Objects → New Object

Nome Cartao, rótulo Cartão de Visita, Scope: Site. Campos:

CampoTipoObrigatório
nomeTextsim
cargoTextsim
telefoneTextsim
emailTextnão
unidadePicklist → Unidadesim

Clique em Publish. Anote o caminho REST que aparece na aba API — deve ser /o/c/cartaos, mas confirme: o plural é derivado do rótulo e pode sair diferente no seu ambiente.

3

Liberar o papel Guest

Control Panel → Roles → Guest → Define Permissions

Busque por Cartao. Marque View no grupo de permissões das entradas e salve.

Não confunda com Objects → Cartao → Permissions

Aquela tela controla a definição do Object — quem enxerga o Object em si. Marcar View lá não torna os registros públicos: cadastros novos continuam devolvendo 404 para visitante anônimo.

A permissão que os registros herdam ao nascer é a do papel, configurada aqui. É a armadilha mais cara desta POC.

4

Importar o fragment set

Design → Fragments → ⋮ → Import

Selecione fragments/bnb-fragments.zip. Deve aparecer o set BNB com dois fragmentos.

Abra Cartao Visita e confira o painel de configuração: há campos para o texto da marca e para o endpoint do Object. Se o passo 2 gerou um caminho REST diferente de /o/c/cartaos, ajuste aqui — ou na instância do fragmento, depois de colocá-lo numa página.

Não existe API REST para importar fragmentos nesta versão; este passo é necessariamente manual.

5

Criar o Display Page Template e marcá-lo como padrão

Design → Page Templates → Display Page Templates → +

Content Type Cartao, nome Cartão de Visita BNB. Arraste o fragmento Cartao Visita para dentro.

Clique no elemento do nome. No painel direito, o ícone de corrente abre o mapeamento: escolha o item atual e o campo nome. Repita para cargo, telefone e email.

Publish e depois, na listagem, menu ⋮ → Mark as Default.

Mark as Default é o interruptor mestre

Só depois dele passam a existir a opção Display Page no mapeamento de link do Collection Display (passo 8) e o Success Action Go to Entry Display Page (passo 6). Se alguma não aparece na interface, volte aqui.

6

Montar a página de cadastro

Site Builder → Pages → + → Blank

Nome Cadastro de Cartão. O card Blank, em Basic Templates, é a Content Page — o diálogo não usa esse termo em lugar nenhum.

No editor, arraste o fragmento Form Container e, no painel direito, aponte o Content Type para o Object Cartao. Os inputs são gerados automaticamente, já mapeados: você não precisa arrastar campo por campo.

Ajustes que restam:

  • remova os campos de sistema que vierem junto (não apaga o campo do Object)
  • ordene: nome, cargo, telefone, email, unidade
  • Success Action → Go to Entry Display Page

Publish.

7

Ignorar o fragmento Redirect Pos Cadastro

Ele vem no ZIP e resolve, via JavaScript, o mesmo problema que o Success Action do passo 6 resolve nativamente: abrir o cartão recém-criado. Se o seu Object tiver display page, não coloque esse fragmento na página — os dois redirecionamentos competem.

Ele só é útil num cenário sem Display Page Template, onde você precisa mandar o usuário para uma página comum com ?id= na URL.

8

Criar a Collection e a galeria

Content → Collections → New → Dynamic

Nome Cartões de Visita, Content Type Cartao, ordenado por nome ascendente, sem filtro.

Crie uma página Galeria (Blank, URL /galeria), arraste o fragmento Collection Display e selecione a coleção.

Monte o layout dentro do primeiro item — ele replica para os demais. Para o link, selecione o elemento, aba Link, escolha Mapped URL e, no campo Field, a opção de display page.

Não mapeie o link para um campo de texto

O editor aceita sem reclamar e produz href="Mariana Figueiredo" em todos os itens. Se a opção de display page não estiver na lista, o passo 5 não foi concluído.

9

Criar a rota alternativa (opcional)

Site Builder → Pages → + → Blank

Uma página Cartao com URL /cartao e o fragmento Cartao Visita solto, sem mapear nada.

O mesmo fragmento funciona nos dois contextos: dentro do Display Page Template ele lê os valores mapeados do DOM; numa página comum ele lê ?id= da URL e busca a entrada pela API. Serve como plano B se o Display Page Template der problema numa apresentação.

10

Popular com exemplos

/cadastro-de-cartao

Use o próprio formulário que você acabou de publicar — é também o primeiro teste real do fluxo completo.

Cadastre quatro ou cinco pessoas, com cargos de comprimentos bem diferentes. Uma galeria com um único registro não demonstra nada, e um cargo longo como "Especialista em Microcrédito" revela na hora se o layout do cartão e o desenho do PNG aguentam texto que não cabe.

Verificação

O único teste que prova as permissões usa registro novo e nenhuma sessão. Registros criados antes podem ter recebido permissão avulsa e passam no teste sem provar nada.

Roteiro em janela anônima

  1. Na janela normal, logado, cadastre alguém em /cadastro-de-cartao
  2. Confirme que você caiu direto na página do cartão recém-criado
  3. Baixar PNG deve gerar o arquivo com os dados corretos
  4. Copiar link deve mostrar a confirmação
  5. Cole esse link numa janela anônima — o cartão precisa abrir sem login
  6. Ainda anônimo, abra /galeria e clique em outro nome

O passo 5 é o que reprova com mais frequência, e o culpado quase sempre é a permissão do passo 3 marcada no lugar errado.

Mesmo teste por linha de comando

Mais rápido de repetir, e a resposta é inequívoca. Pegue o id do cartão que você acabou de criar e consulte sem credenciais: 

curl -s -o /dev/null -w "%{http_code}\n" http://localhost:8080/o/c/cartaos/<id>

200 → permissão correta, o cartão é público
404 → falta a permissão de ENTRADA para Guest (passo 3)
404 e não 403

Quando falta permissão de entrada, o Liferay responde 404. Parece registro inexistente, e é fácil perder tempo procurando erro de dado onde há bloqueio de acesso.

Quando algo falha

SintomaCausa mais provável
Cartão mostra "Nome da Pessoa" Sem ?id= e sem mapeamento. No Console procure o aviso [cartao-visita] com o status HTTP.
Botão Baixar PNG sempre desabilitado Os dados não carregaram — é o comportamento correto, para não exportar placeholder.
404 anônimo em registro novo Passo 3 incompleto: a permissão foi marcada na tela do Object, não no papel.
409 ao listar pela API Object com escopo Site exige /scopes/<groupId> no caminho.
Formulário não redireciona Success Action não está em Go to Entry Display Page, ou o template não foi marcado como padrão.
Links da galeria todos iguais ou quebrados Link mapeado para um campo de texto em vez da display page.

Armadilhas

Permissão do Object não é permissão das entradas

São recursos distintos. O sintoma de faltar a permissão de entrada é 404, não 403 — parece registro inexistente, e você perde tempo procurando erro de dado.

Content Page se chama "Blank"

O diálogo de nova página não usa o termo em lugar nenhum. Tudo que está em Other são outros tipos. Sinal de acerto: a página abre no editor com o painel de Fragments.

Sem data-lfr-editable não há mapeamento

O ícone de corrente só aparece em elementos com data-lfr-editable-id e data-lfr-editable-type. Um fragmento sem esses atributos parece não suportar mapeamento. O Cartao Visita já vem com eles.

Fragmentos e páginas não têm REST

Não há endpoint para importar fragment collections — a API expõe apenas fragment compositions, que são outra coisa. E POST /site-pages responde UnsupportedOperationException. Importar o ZIP, criar páginas e arrastar fragmentos são sempre manuais.

O plural do endpoint não é garantido

/o/c/cartaos foi o gerado no ambiente de origem, mas o caminho deriva do rótulo do Object. Confirme na aba API antes de fixá-lo no campo objectEndpoint da configuração do fragmento.

Referência

Endpoints do Object

Não são necessários para montar a POC — o Liferay os gera sozinho e a interface cobre todo o fluxo. Ficam aqui para depuração e para quem for integrar outro sistema. 

# uma entrada — dispensa o escopo
GET    /o/c/cartaos/{id}

# listagem — exige o escopo em Objects site-scoped
GET    /o/c/cartaos/scopes/{groupId}?pageSize=50&sort=nome:asc

# criação
POST   /o/c/cartaos/scopes/{groupId}
       {"nome":"...","cargo":"...","telefone":"...","unidade":{"key":"TI"}}

# atualização parcial e remoção
PATCH  /o/c/cartaos/{id}
DELETE /o/c/cartaos/{id}

# permissão de UMA entrada (a de modelo não tem REST)
PUT    /o/c/cartaos/{id}/permissions
       [{"actionIds":["VIEW"],"roleName":"Guest"}]

# administração
GET    /o/object-admin/v1.0/object-definitions
GET    /o/headless-admin-user/v1.0/my-user-account   mostra os sites

O que o fragmento Cartao Visita faz

  • Renderiza o cartão com a faixa em gradiente. Funciona com campos mapeados (display page) ou buscando por ?id= (página comum).
  • Exporta PNG desenhando em canvas 2D nativo — sem biblioteca externa. Não é captura de tela: se você mudar o CSS do cartão, ajuste também a função de desenho em index.js.
  • Copia o link com navigator.clipboard, com fallback para execCommand fora de contexto seguro (HTTP sem TLS).
  • Desabilita a exportação enquanto os dados não carregam, para nunca gerar um PNG com texto de placeholder.

Adaptar para outro cliente

As quatro cores da marca estão no topo de fragments/bnb/cartao-visita/index.css, como variáveis CSS em .bnb-wrap. Trocar ali muda o cartão na tela. O PNG tem os valores repetidos em index.js, na função de desenho — é o único ponto de duplicação consciente do projeto, porque o canvas não lê CSS.

Para aplicar a identidade ao site inteiro (header, botões, links), o caminho é um Style Book em Design → Style Books, não CSS espalhado por página.
